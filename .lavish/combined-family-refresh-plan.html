What gap does this close?

We can bring records across

The existing importers add tags, custom fields, notes, tasks and historical metadata. They protect records by refusing to overwrite different values.

Now we need to bring changes across

If a source note changes, a task is completed, or a field gets a new value after the first import, we need a safe way to update it.

This package adds that later-refresh ability for original, later-admitted and recovered People.

What changes in each group?

01

Tags & custom fields

Add qualified new values and update unchanged imported values. Keep catalog and option mappings explicit.

P2: removing an imported tag link or clearing a field needs clear source evidence and an exact counted acknowledgement.

Keep local tags. Never delete shared definitions. Missing data does not mean “remove it.”

02

Notes & tasks

Add new records; refresh untouched imported notes and task details. A source task can complete or reopen an unchanged imported task.

Show reopen/completion counts explicitly. Preserve readable-note conversion, authorship and confirmed timezone rules.

A local edit, snooze, reassignment or completion holds that record. No disappearing record is silently deleted.

03

Historical metadata

Add new events, calls and texts. If an existing source record changes, append a correction version.

P3: show one current timeline entry, with a way to inspect the earlier metadata and where the correction came from.

Keep old facts intact. No message bodies, recordings or invented contact credit.

A correction is not another call

Source call #42 changes

The first capture said the duration was 20 seconds. A later qualified capture says 45 seconds.

We preserve both observations, each tied to its source capture. Conflicting versions inside the same capture remain held.

The timeline still has one call

Its current metadata shows 45 seconds and a correction label. “Earlier versions” shows the prior 20-second value.

We do not rewrite the original fact, inflate the call count, or treat imported metadata as a native contact attempt.

P4 · One approval does not mean one giant transaction

A transaction is a set of database writes that succeeds or rolls back together. We use small transactions: one Person’s metadata, one note, one task, or one historical identity.

Crash before commit

That unit rolls back. When the worker’s claim expires, a worker can retry the same unit.

Crash after commit

The saved result proves the unit finished. A retry recognizes it instead of doing it twice.

Cancel or pause

Already completed work stays. Other groups can continue. Any remainder includes only unfinished approved work.

Use the existing worker scheduling at one second. This plan adds no extra pods or three separate polling loops. Worker supervision and PgBouncer remain separate work.

Keep the boundaries visible

What if a source record disappears?

Report “not observed” or “inaccessible.” Absence is not an instruction to delete a CRM record. Explicit owned tag removals and field clears are the narrowly defined exceptions, and need counted approval.

What if first import coverage is missing?

Show that prerequisite and link to the existing first-import workflow. We will not invent a baseline or quietly start another import. Successful units from cancelled imports can qualify; their remaining gaps stay visible.

Does this finish migration?

No. This closes qualified later additions, updates and corrections. Full cutover, workspace activation, source deletion policy, unsupported source data, email/media and customer erasure readiness remain separate.

Will this deploy anything?

No. The user explicitly deferred deployment. Shared development remains 010e5; 010e6 and this package can be released together after a later deployment instruction.

Review the four policies, then approve the package

The combined approach is planned. P1–P4 make the new behavior explicit: protect local work; allow only proven and counted clears/removals; preserve history corrections; confirm once with independently tracked progress.

Nothing is selected or submitted automatically.
