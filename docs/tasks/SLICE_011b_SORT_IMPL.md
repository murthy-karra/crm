## Outcome

Agents order any People list by Added, Name, Stage or Assignee in either
direction; the server orders before the 500 cap; saved lists persist their
sort as part of the definition; Today ignores it; without a sort nothing
changes.

## Exclusions

Derived-column sorts, per-viewer preferences, multi-column sort, indexes,
Lists-index sorting, Today, Operator, counts, mobile, any change to
`FilterDefinition`, any change to the default statements' text.

## Order of work and checks

1. Type and parser with unit tests; the seven statements and the text-parity
   test; `./scripts/sqlx-prepare`; prove the default entries' hashes unchanged.
2. Route parameter decoded in the typed query extractor so malformed values
   are 400 before pool acquisition (the service-free route tests depend on
   it); error precedence with HTTP tests; DB ordering, truncation,
   composition and isolation tests.
3. Migration, commands, reads, fingerprint rule, fail-closed decode, saved-list
   and schema tests, Today parity test.
4. Performance measurement per spec §4 at 100k People in one seed run;
   record generic-plan `EXPLAIN (ANALYZE)` loop counts and percentiles; apply
   the pre-declared `latest_src` guard and then the plan-cache lever only if
   measured necessary, re-measuring after each.
5. Web: sort helpers, DataTable headers, Added column, PeopleView URL and
   draft integration, dialog summary line, cap message, tests.
6. `./scripts/check`, then `./scripts/check-db`, once on the final tree.
7. Handoff: changed files reconciled against `git status`, criterion-to-test
   mapping, commands and results, `.sqlx` hash list, limits. Note for the
   shared runtime: `./scripts/db-migrate` before the dev API is restarted.
